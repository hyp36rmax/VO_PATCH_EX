# Playable Bosses in Experience

This isolated development branch integrates upstream single-player Playable
Bosses from `4ecae6237e1fc432c0be2f2b0aeab5303120e444`, based on Experience
`6b22b0dcd490eec8b6a3e953d881649e74ab26cb`. Pairomaniac maintains the original
V-On Patcher; Vortyne implemented Playable Bosses; hyp36rmax maintains the
VO PATCH EX integration and expansions. The [upstream technical record](../BOSSES.md)
retains the implementation details and portrait licensing boundaries.

## Player behavior

Playable bosses is optional and off by default. Pre-unlock the bosses is disabled
unless Playable bosses is selected. Jaguarandi and Z-Gradt retain upstream
single-player selection, weapons, movement, camera, progression, replay and ending
behavior; no balance changes or Local VS boss controls are added. Z-Gradt's laser
uses the game's existing Dash/turbo action, independent of the physical controller.

Unlock progression is stored in `bosses.bin` beside the game. Restore Original
preserves it. Use Restore Original before repatching an existing installation.
A failed integrated Apply restores the previous progression file, including its
absence, together with the rest of the transaction. Successful pre-unlock retains
upstream behavior: write level 2 without reducing existing valid progress.

## Integration decisions

| Area | Adaptation / evidence |
|---|---|
| Boss code | Upstream assembly and portrait sources are byte-identical to the pinned commit. CE's larger annex relocates the boss section through the existing linker. |
| Hangar shading | Experience's UI hangar entry is eight bytes later than upstream. All edition symbols use `UI_HANGAR_DRAW`; hardcoded OEM/JPRE offsets would recover the wrong UI base. No boss assembly change is needed. |
| Catalog identity | Preserve bits 0–7: hires, padxinput, nodisc, debugbox, defaults, sound, movie, credits. Append bosses at bit 8 and bossunlock at bit 9. Existing masks 0–255 keep their meanings. |
| Recipe coverage | 1,024 masks per integrated edition, 2,048 total. Pre-unlock has no executable writes, so its recipes reuse the generated executable result with a distinct requested-mask field. The upstream dependency still rejects pre-unlock alone. |
| Source verification | Regenerated sparse recipes remain locked to source hashes, pristine/base/final executable hashes and exact runtime identities. The generator and catalog verifier are included in the source lock. No generated bytes are edited manually. |
| Offline generation | Reuse one private module instance within the generator to avoid recompiling embedded tables for each profile. Generators read these tables; output reconstruction and representative uncached comparisons check this optimization. |
| Apply / Restore | Add `bosses.bin` and its temporary/backup names to failed-Apply snapshots. Progression remains outside installed-runtime ownership, so successful Restore does not remove it. |
| Existing features | Controller, networking and display implementations are retained. Historical whole-image regression comparisons explicitly disable the new optional patches. |

| Boss gameplay, unlock/restart behavior, cameras, replay and endings on Windows | NEEDS VALIDATION |
| Boss camera/model/portrait presentation at 4:3, 16:9, 21:9 and 32:9, dual modes and mixed monitors | NEEDS VALIDATION |
| Local VS boss play | UNSUITABLE for this milestone; upstream selection retains eight machines |

The private UAT package must be exercised on Windows before integration into
Experience. Check normal patcher launch, option dependency, Apply, game startup,
both boss selections and attacks, earned and pre-unlocked progression, restart,
all existing F5/F7 settings, clean exit and Restore. Retest the original eight
machines with bosses disabled. Boss-specific input tests should include each
lever's dash/turbo, press/hold/release and mixed controller ownership.

Do not infer acceptance of later gameplay or every monitor combination from
successful patch generation. No public release or Experience merge is part of B01.
